# 08 — Functional architecture glossary

**Status:** `TARGET_DESIGN` · Product-owned normative terms and exact schema fields take precedence when a published contract defines them.

| Term | Meaning in the final functional system |
|---|---|
| **Acceptance** | Receiver or authority acknowledges a scoped request or artifact. It does **not** imply that any asynchronous effect has completed. |
| **Activation** | A named runtime/product/Space state transition with owner-authorized and measured results, distinct from publication. |
| **Admission** | A receiving owner or enforcing system decides an exact input/profile may enter its controlled boundary. |
| **Agentic job** | A bounded, checkpointed AI workflow controlled by Konductor and unable to create other products' state without their contracts. |
| **Approval** | A scoped decision issued by the legitimate owner; not automatically implied by an independent test. |
| **Arketype** | Non-normative shape/template material for authoring; not a source of canonical identity or truth. |
| **Artifact digest** | Cryptographic identity of exact bytes; confirms those bytes, not their correctness, licensing or deployment. |
| **Authoring Kit** | Local owner-controlled Kristal workspace, validation and build tooling, distinct from Framework and public publisher. |
| **Boundary** | Point where ownership, trust, contract version or effect authority changes; requires both producer and receiver decisions. |
| **Canonical semantic identity** | Framework-governed identity such as KQ/KP/KA/KS; independent of labels and external Q/P identifiers. |
| **Case / Task** | Durable operational units owned by Orgo, not by education previews, civic decision records or an agent prompt. |
| **C0** | kOA Digital Ecosystem coordination/documentation scope; descriptive architecture and evidence navigation, not product authority. |
| **Collection / read view** | Immutable authorized publication or rebuildable derived representation of pinned semantic/source input. |
| **Composition** | Scenario combining selected functional chains, not a mandatory synchronous transaction. |
| **Crosswalk** | Reviewed mapping between external provider IDs and internally defined identities; does not automatically merge or replace them. |
| **DecisionRecord** | Finalized Konnaxion civic decision with its own legitimacy rules, separately consumed as an execution intent. |
| **Derived projection** | Rebuildable downstream representation (reader index, context, Moodle object, UI view) that cannot acquire upstream authority. |
| **DaaT** | External mapping and admission boundary with explicit host-provided security and owner contract checks. |
| **Diagnostic verdict** | Independent evidence about a pinned subject under a named campaign; not a release or policy grant. |
| **EncyK** | Source-acquisition/intake engine integrated in Skope in the observed target owner documentation. |
| **EncyKlopedia** | Distinct public multilingual encyclopedia/read product, not the Skope acquisition engine. |
| **Execution terminal state** | A reconciled succeeded/failed outcome backed by owner observation, not mere command acceptance. |
| **External Q/P** | Wikidata-like provider Q/P identifiers; not interchangeable with canonical Kristal KQ/KP. |
| **Framework profile** | Exact versioned semantic conformance rules; observed v11 drafts are candidates until approved and qualified. |
| **Functional chain** | A bounded final-system capability specifying initiation, state owners, stages, outputs, forbidden effects and evidence gates. |
| **GF / RuntimeSet** | Grammar/realization runtime family used by SemantiK under pinned, qualified deployment contracts; grammar truth stays with grammar owners. |
| **Idempotency** | Same request intent/key does not cause a second real effect; changed intent under same key is a conflict. |
| **Interaction Kernel (IK)** | Versioned envelope/profile semantics explicitly adopted by a boundary, not a universal central stateful service. |
| **KQ/KP/KA/KS** | Framework semantic namespace identities kept separate from lexical and external identifier layers. |
| **Konductor** | Agentic workflow control plane design/implementation owner; not an alternate Orgo Case/Task authority. |
| **Konfid / PEP** | Scoped policy decision system and the actual policy enforcement point at the owner that can stop effects. |
| **KristalDiag** | Independent diagnostic tool for exact Kristal artifacts; not a semantic owner or publisher. |
| **Lexical fallback** | Consumer-labeled fallback in a language where a direct approved term is absent; not evidence of a certified translation. |
| **Local build** | Reproducible artifact from the Kit/profile, not an independent test or public release. |
| **Médiathèque instance** | Separately controlled source custody database/library using the shared engine; data authority is instance-scoped. |
| **Moodle projection** | UCKK/institution-owned educational materialization; does not become semantic canon. |
| **Owner** | Product/institution that may legitimately decide or mutate its own authoritative state. |
| **Owner snapshot** | Exact user-supplied files with recorded hash, not current remote Git HEAD or a live production observation. |
| **Publication** | Explicit owner-authorized write of an artifact to a named audience/target with immutable/replayable release record. |
| **Qualified bilateral boundary** | Exact producer and consumer revisions tested against the same approved interface with valid and invalid fixtures. |
| **Receipt** | Receiver/host-owned durable evidence of acceptance, terminal effect, import, publication or activation as appropriate. |
| **ReleaseSet** | Named compatible signed/admitted group of deployable artifacts under a platform profile; product/host owners determine exact schema. |
| **Replay** | Re-delivery of an immutable intent; equal inputs return prior receipt; divergent inputs fail. |
| **Research candidate** | Proposed entity/source/mapping from acquisition or models; not a canonical Kristal assertion. |
| **Runtime activation** | Host-controlled effect of selecting/running an admitted revision with measured health. |
| **Skope** | Owner of bounded local research scopes and integrated EncyK source acquisition. |
| **Space** | Koali Spaces optional presentation/navigation lifecycle, not an owner business transaction. |
| **Tenant / World** | Contract-bound scopes for identity, data, authority and context; never inferred solely from UI route. |
| **Target design** | The final-system destination and acceptance requirement, not implementation proof or a commitment by an owner. |
| **WorldRelease** | Product-owned, versioned Universe/World configuration/context admitted by the correct app, not a universal authorization token. |

## Vocabulary discipline

Use **"designed"** for specification intent, **"observed in a snapshot"** for source bytes, **"locally tested"** for named owner test evidence, **"bilaterally qualified"** for exact producer/consumer proof, **"release authorized"** for explicit owner grant, and **"deployed observed"** only for measured named-environment evidence. Do not call an illustrative scenario a production workflow or a proposed connection an adopted protocol.
