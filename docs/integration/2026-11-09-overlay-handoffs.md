## Handoff acceptance requirements

For a real bilateral release, record producer/consumer repo/revision, precise interface and schema, example accepted/denied inputs, authentication and actor/tenant scope, stable idempotency, immutable acceptance/terminal receipts, privacy classification, rollback and the **actual** two-sided test logs. A document or unit test on just one side does not qualify the connected function.

**Do not:** add missing branch 05 product code from older archive snapshots, infer deployment from GitSink cached statuses, auto-push public Git, convert unsigned receipts into signatures, or copy private source/medical/student data into the C0 public-site projection.
